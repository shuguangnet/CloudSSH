# 数据库连接与 MCP 数据库工具

自托管运行时内置外部数据库接入能力：面板提供 `/database` 页面管理连接与代理，同一套连接配置同时通过 MCP 暴露给外部 AI 客户端调用。设计目标是**不新增任何入站端口**——数据流量始终由面板出站发起，MCP 复用已有的 `/mcp` 端点。

## 能力边界

| 引擎 | 默认端口 | 驱动包 | 备注 |
| ------ | -------- | -------- | ------ |
| MySQL | 3306 | `mysql2` | MariaDB 共用同一驱动 |
| MariaDB | 3306 | `mysql2` | 与 MySQL 同一实现，协议兼容 |
| PostgreSQL | 5432 | `pg` | 支持 TLS |
| Redis | 6379 | `ioredis` | 命令数组直接作为 `params` 传入 |

驱动为**可选依赖**：未安装时对应引擎的连接在页面上标记为不可用，`/database` 顶部给出安装命令，MCP 侧 `db_test` 返回 `driverMissing`。安装方式：

```bash
pnpm add -w pg mysql2 ioredis
```

随后重启面板进程（或重建 Docker 镜像）。`/api/db/drivers` 会随安装结果实时变化。

## 代理：统一在 TCP 层解决

代理不是逐个驱动实现的，而是在 TCP 层做**本地回环端口转发**：面板先按代理配置建立到目标数据库的隧道，再在 `127.0.0.1` 上开一个临时端口，驱动连到这个本地端口即可。因此：

- 驱动完全感知不到代理的存在，MySQL SSL、PostgreSQL TLS、Redis RESP 都不受影响；
- 新增引擎不需要再写一遍代理逻辑；
- 隧道只监听回环地址，不对局域网暴露；
- 空闲 120 秒自动回收，连接池复用期间不会频繁重建。

支持的代理类型：

| 类型 | 说明 | 必填字段 |
| ------ | ------ | -------- |
| 直连 | 不使用代理 | — |
| SOCKS5 | 支持用户名/密码认证（RFC 1928 / 1929） | `host` `port`，可选 `username` `password` |
| HTTP CONNECT | 常见的企业 HTTP 代理 | `host` `port`，可选 `username` `password` |
| SSH 跳板 | 复用面板的 SSH 会话与密钥 | `host` `port` `username` + 密码或私钥 |

**关于 OpenVPN**：容器运行在 `read_only` + `cap_drop: ALL` 下，无法在进程内创建 TUN 设备。需要通过 VPN 才能到达的数据库，请在宿主机上建立隧道后再让数据库监听回环/桥接地址，面板侧用「直连」或「SSH 跳板」指向即可。

## 配置存储

数据库配置独立存放于 `DATA_DIR/database.sqlite`（与用户数据库、SSH 数据分开），三张表：

- `db_proxies`：代理定义（类型、地址、凭据）
- `db_connections`：连接定义（引擎、主机、库名、只读开关、引用的代理）
- `db_audit`：查询审计记录

连接密码用 AES-256-GCM 加密，密钥来自 `DATA_DIR` 下独立的密钥文件（权限 `0600`，scrypt 派生）。**接口从不回显密码**：读取连接时只返回 `hasPassword` 布尔值，编辑表单密码框留空即保持原密码。删除仍被连接引用的代理会被拒绝（400），避免静默断开线上连接。

## 页面操作

`/database` 分为驱动状态、连接、代理、控制台、审计五块：

1. **连接**：选择引擎后自动填充默认端口；「只读」开关默认开启。「测试连接」可在保存前先验证，也可对已保存连接做二次验证。
2. **代理**：SSH 类型会隐藏 host/port 之外的直连字段；密码同样只写不读。
3. **控制台**：选择连接后执行 SQL（`Ctrl/Cmd + Enter` 快捷执行），结果表格最多展示 200 行 / 100 列，单格超过 4096 字符截断。写语句在只读连接上会被直接拒绝。
   结果单元格命中密钥模式（私钥块、Bearer token、`PASSWORD=`、连接串口令、`sk-`/`ghp_` 密钥、JWT）时按 `***` 遮蔽，状态栏会显示遮蔽数量——**数据库里仍是原值**，界面只是不把它显示出来。
4. **审计**：最近 500 条记录，含连接名、工具、状态、耗时与 SQL 指纹。

## MCP 工具

沿用已有的 `read` / `write` 授权维度，不引入新 scope。区别在于数据库工具还需要 token 上额外的 `db_connection_ids` 白名单——即使 token 有 `read` scope，也只能访问显式授权的连接。

| 工具 | 需要的 scope | 说明 |
| ------ | ------------- | ------ |
| `db_list_connections` | 无 | 列出该 token 可见的连接（名称/引擎/主机/只读标记，不含密码） |
| `db_schema` | `read` | 列出库中的表/集合，或某张表的列定义 |
| `db_query` | `read` | 执行只读查询；写语句会被拒绝 |
| `db_exec` | `write` | 执行写语句；面向只读连接的 token 无法调用 |
| `db_test` | `read` | 连通性测试，返回延迟与错误分类 |

`db_exec` 会在授权层显式拒绝只读连接——不会因为 token 拥有 `write` scope 就绕开连接的只读开关。

### 审计原则

审计表 `mcp_audit` 与 `db_audit` 只记录**元数据**：

- SQL 语句只存 `sql_sha256` 指纹，供比对两次是否为同一条语句；
- 不记录 SQL 原文，不记录任何查询结果或返回的行数以外的内容；
- 密码与私钥从不出现在日志、审计或 API 响应中。

指纹而非原文的取舍：需要复盘具体语句时，用原文重新计算 SHA-256 即可确认是否为同一条记录，而历史库本身不构成一份敏感数据副本。

## 相关接口

页面使用以下接口（均要求已登录会话 + 同源校验）：

| 路由 | 方法 | 说明 |
| ------ | ------ | ------ |
| `/api/db/drivers` | GET | 驱动安装状态 |
| `/api/db/proxies` | GET / POST | 代理列表 / 新建 |
| `/api/db/proxies/:id` | PATCH / DELETE | 更新 / 删除（被引用时 400） |
| `/api/db/connections` | GET / POST | 连接列表 / 新建 |
| `/api/db/connections/:id` | PATCH / DELETE | 更新 / 删除 |
| `/api/db/connections/:id/test` | POST | 测试已保存连接 |
| `/api/db/query` | POST | 执行查询（只读连接只允许读语句） |
| `/api/db/audit` | GET | 审计记录（`limit ≤ 500`） |

错误码到 HTTP 状态的映射：`invalid` → 400、`notFound` → 404、`driverMissing` → 501、`readOnly` → 403、`query` / `connect` → 502。

## 安全边界

- 数据库连接只由服务端发起，浏览器与 MCP 客户端都不直接接触数据库；
- 代理隧道只绑定回环地址，且空闲自动回收；
- 连接密码加密存储，接口只暴露 `hasPassword`；
- 只读开关在连接层生效，`db_exec` 不会绕开它；
- 只读判定走 `standalone/sql-safety.mjs` 的**词法扫描**，而不是正则匹配：按引号 / 注释 / dollar-quote 切出裸词 token，逐语句取动词并检查任意深度的写关键字。因此 `WITH x AS (DELETE ...) SELECT`、`SELECT ... INTO OUTFILE`、`FOR UPDATE`、MySQL 可执行注释、注释拆词都不能绕过；含反斜杠的输入按 MySQL 与 PostgreSQL/SQLite 两种语义各扫一遍，只要有一遍暴露出写操作就拒绝（并提示改用 `''` 转义）。
- 查询结果在返回前做秘密脱敏兜底，命中数量通过 `redactedCells` 上报；
- 审计只存 SQL 指纹，不构成敏感数据副本。

### 只读闸门的定位

它是**防手滑与防误配**，不是权限边界。真正的权限控制应该由数据库侧的只读账号完成——面板的只读开关只保证「不会从这条连接发出写语句」，无法约束一个拥有写权限的账号在别处执行写操作。请为只读用途单独创建只读账号。

### 连接健壮性

| 机制 | 作用 |
| ------ | ------ |
| TCP keepalive（30s） | NAT / 防火墙静默丢流时，让死连接在空闲期就暴露，而不是等用户踩上去 |
| 空闲探活（30s） | 池内连接空闲超过阈值时，复用前先 ping；失败即丢弃重建并返回 `connect` 错误 |
| 有界拆除（5s） | `pool.end()` 在死传输上会等一个永不回来的 FIN；超时后强制销毁 socket，避免整个池永久挂住 |
| 池自愈 | 服务端终止会话后，下一次查询自动重建连接，无需人工重启面板 |
